### Process: where BMAD was ceremony or friction (from this session)

- **Reviewer noise.** Triage logs show roughly a third of findings patched; the rest were rejected, false or deferred (12.1: 4 patch / 8 defer / 3 false / 2 reject; 12.2: 5/7/4/3; 12.3: 8/2/3/5; 12.4: 6/3/2/7; 12.5: 7/1/4/2, counted from each spec's triage log). Verifying every claim is the real cost of the review layers.
- **Backfilling a brownfield repo** (PRD, spine, epics 0–11) was needed for traceability but took effort with no product change.
- **Completeness gate** blocked the retro because stories sat at `review` without a separate `bmad-code-review`; the in-build four-layer review made that step redundant here.
- **Spec memlog discipline** (`SPEC.md` derived, never hand-edited) adds steps for small wording fixes.
- **Environment friction:** uv not installed (Homebrew built from source; installed via PyPI instead), no `java` on PATH (`JAVA_HOME` needed), the VS Code Java extension compiling into `target/` mid-run (fixed with `clean`, twice), and Docker needing a start before every commit.
- **Gaps in this pilot's own setup, found by running it:** the repo-invariants reviewer was missing from the oneshot route; story specs didn't list the epic spine in `context:` (12.2); the epic-wide oneshot reviewer scope missed `docs/` until widened.

### Cost and speed (subagent usage reported by the harness)

- Developer subagents: 115–154k tokens each including review fixes; 6–12.5 minutes per dispatch story.
- Review layers: 60–95k tokens each, 36–98 seconds, run in parallel (four on dispatch stories, two on oneshot).
- Cross-story review: 163k tokens, ~4 minutes.
- Total subagent usage for the epic: roughly 1.5M tokens. Oneshot stories (12.1, 12.3) cost about a third of a dispatch story.
